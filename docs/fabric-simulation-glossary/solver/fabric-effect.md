Owns the particle buffers and runs the solver: each step is a series of compute dispatches of <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-compute-fx/">`FabricCompute.fx`</a> over the sheet, whose positions stay on the GPU.

A sealed class that implements `IDisposable`, in the namespace `BorrowedTorch.FabricSimulator.Simulation`. Double-buffered: the passes read neighbors, so updating in place would race. Each instance runs its own copy of the loaded effect, so any number of sheets can share one `ContentManager`, one `FabricEffect` each. A <a class="ref" href="/docs/fabric-simulation-glossary/sheet/fabric/">`Fabric`</a> drives it; without one, <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>, <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#apply">`Apply`</a> and <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#update">`Update`</a> do. Three read-only record structs nested in it carry its diagnostics: <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect-spatial-hash-overflow/">`FabricEffect.SpatialHashOverflow`</a>, <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect-step-motion/">`FabricEffect.StepMotion`</a> and <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect-coincident-contacts/">`FabricEffect.CoincidentContacts`</a>. The [sheet and step page](/docs/fabric-simulation-sheet/#fabriceffect-stepping-members) shows it in context, with code. Use it from the thread that owns the graphics device.

Names are colored by what they are: a <span class="kb kb-prop">property</span> or a <span class="kb kb-method">method</span>; values and fields keep the plain color.

## Properties

<h3 id="dispatchesperstep"><span class="prop"><code>DispatchesPerStep</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="DispatchesPerStep in context on the sheet and step page" aria-label="DispatchesPerStep in context on the sheet and step page">→</a></h3>

`int` · Read-only. The compute dispatches one step makes, as the settings last applied decide: one to integrate; one per round of <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#relaxationiterations">`RelaxationIterations`</a>, at least one, and one more for each round that solves bending; three for self-collision, to clear the spatial hash, fill it and gather each point's partners; and with <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#useaerodynamicpressure">`UseAerodynamicPressure`</a>, one per level of its pyramid. Per step, not per frame: times <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#laststepcount">`LastStepCount`</a> for a frame, and at a high frame rate most frames run none.

<h3 id="interpolationfraction"><span class="prop"><code>InterpolationFraction</code></span> <a class="ctx" href="/docs/fabric-simulation-drawing/#fabriceffect-drawing-properties" title="InterpolationFraction in context on the drawing page" aria-label="InterpolationFraction in context on the drawing page">→</a></h3>

`float` · Read-only. Where to draw between the last two steps, from 0, the previous step's pose, to 1, the latest. Chosen so the drawn cloth moves evenly at the least constant lag the frame rhythm allows: none when frames line up with the steps, where it settles at 1, as under MonoGame's fixed 60 Hz; 3.5 ms on average at 144 Hz; never more than a step. When the rhythm changes, the lag rises at once and sheds slowly, so the cloth never jumps. Bind it to a uniform of your own every frame, for <a class="ref method" href="/docs/fabric-simulation-glossary/hlsl/fabric-particle-buffer-fxh/#fabricevaluatevertex">`FabricEvaluateVertex`</a> or <a class="ref method" href="/docs/fabric-simulation-glossary/hlsl/fabric-particle-buffer-fxh/#fabricinterpolatedposition">`FabricInterpolatedPosition`</a>. Follows <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#update">`Update`</a>; <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#step">`Step`</a> alone leaves it where it was.

<h3 id="issaturated"><span class="prop"><code>IsSaturated</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="IsSaturated in context on the sheet and step page" aria-label="IsSaturated in context on the sheet and step page">→</a></h3>

`bool` · Read-only. Whether the last <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#update">`Update`</a> ran <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#maxstepsperframe">`MaxStepsPerFrame`</a> steps and still owed time, which it dropped rather than carry into the next frame: the cloth ran slower than the clock that frame. `false` after <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

<h3 id="laststepcount"><span class="prop"><code>LastStepCount</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="LastStepCount in context on the sheet and step page" aria-label="LastStepCount in context on the sheet and step page">→</a></h3>

`int` · Read-only. How many steps the last <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#update">`Update`</a> ran: 0 for a frame shorter than what was left of a step, two a frame under MonoGame's fixed 60 Hz at the default 120 Hz, at most <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#maxstepsperframe">`MaxStepsPerFrame`</a>.

<h3 id="particlebuffer"><span class="prop"><code>ParticleBuffer</code></span> <a class="ctx" href="/docs/fabric-simulation-drawing/#fabriceffect-drawing-properties" title="ParticleBuffer in context on the drawing page" aria-label="ParticleBuffer in context on the drawing page">→</a></h3>

`StructuredBuffer` · Read-only. The particles as of the latest step, one <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-particle/">`FabricParticle`</a> record each, in the layout <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-particle-buffer-fxh/">`FabricParticleBuffer.fxh`</a> declares, for your vertex shader's <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-particle-buffer-fxh/#fabricparticles">`FabricParticles`</a>. Bind it every frame: the solver keeps two record buffers and swaps them as it steps, and <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a> replaces them. `null` before the first `SetParticles`, and after <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#dispose">`Dispose`</a>. Never bind it to the solver's own effect, which declares no `FabricParticles`.

<h3 id="particlecount"><span class="prop"><code>ParticleCount</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-particle-methods" title="ParticleCount in context on the sheet and step page" aria-label="ParticleCount in context on the sheet and step page">→</a></h3>

`int` · Read-only. The particles the buffers hold: 0 before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a> and after <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#dispose">`Dispose`</a>.

<h3 id="shader"><span class="prop"><code>Shader</code></span> <a class="ctx" href="/docs/fabric-simulation-wind/#fabriceffect-shader-property" title="Shader in context on the wind page" aria-label="Shader in context on the wind page">→</a></h3>

`Effect` · Read-only. This sheet's own copy of the compiled solver, cloned from the one the `ContentManager` loaded and disposed with it: the place to set a wrapping effect's own uniforms, such as a wind function's knobs. Set them here, not on the instance `Content.Load` returns, which every `FabricEffect` copies from. Not for drawing: it declares no <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-particle-buffer-fxh/#fabricparticles">`FabricParticles`</a>. Leave its grid sizes and buffers alone: <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a> sets them, and the solve depends on them.

<h3 id="time"><span class="prop"><code>Time</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="Time in context on the sheet and step page" aria-label="Time in context on the sheet and step page">→</a></h3>

`float` · Read-only. Simulated seconds since the sheet was uploaded: one <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#timestep">`TimeStep`</a> more at every step. A clock for your own gusts, which should follow the cloth rather than the frame when it falls behind. Wind functions in HLSL see it as <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-compute-fx/#fabrictime">`FabricTime`</a>. Back to 0 at <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

<h3 id="totalstepcount"><span class="prop"><code>TotalStepCount</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="TotalStepCount in context on the sheet and step page" aria-label="TotalStepCount in context on the sheet and step page">→</a></h3>

`long` · Read-only. Steps since the sheet was uploaded. Back to 0 at <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

## Fields

<h3 id="computegroupsize"><code>ComputeGroupSize</code> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-limits" title="ComputeGroupSize in context on the sheet and step page" aria-label="ComputeGroupSize in context on the sheet and step page">→</a></h3>

`int` · Constant, 256. Threads per compute group: each dispatch covers the sheet in groups of this many. Must equal `GroupSize` in `FabricSimulation.fxh`, or each dispatch covers only part of the sheet, and the rest freezes; the constructor checks it when it can find the header.

<h3 id="contactcandidatecapacity"><code>ContactCandidateCapacity</code> <a class="ctx" href="/docs/fabric-simulation-collisions/#fabriceffect-self-collision-constants" title="ContactCandidateCapacity in context on the collisions page" aria-label="ContactCandidateCapacity in context on the collisions page">→</a></h3>

`int` · Constant, 32. The self-collision partners each point keeps per step: gathered once a step, tested at every round that solves contacts. Must equal `ContactCandidateCapacity` in `FabricSimulation.fxh`, which the constructor checks as it does <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#computegroupsize">`ComputeGroupSize`</a>. A point with more partners loses the rest for that step, which only a crushed pile reaches; <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#samplespatialhashoverflow">`SampleSpatialHashOverflow`</a> reports it.

<h3 id="defaulteffectpath"><code>DefaultEffectPath</code> <a class="ctx" href="/docs/fabric-simulation/#the-shaders-in-your-content" title="DefaultEffectPath in context on the quick start guide" aria-label="DefaultEffectPath in context on the quick start guide">→</a></h3>

`string` · Constant, `"Effects/Fabric/FabricCompute"`. Where the package's content build puts the compiled solver, for a `ContentManager` rooted at `Content`: what the constructor loads unless told otherwise.

<h3 id="maxparticles"><code>MaxParticles</code> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-limits" title="MaxParticles in context on the sheet and step page" aria-label="MaxParticles in context on the sheet and step page">→</a></h3>

`int` · Constant, 16,776,960: 65,535 groups of <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#computegroupsize">`ComputeGroupSize`</a>, the most one compute dispatch can cover. The largest sheet: <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#rebuild">`Rebuild`</a> and <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a> refuse more.

<h3 id="spatialhashmaxpercell"><code>SpatialHashMaxPerCell</code> <a class="ctx" href="/docs/fabric-simulation-collisions/#fabriceffect-self-collision-constants" title="SpatialHashMaxPerCell in context on the collisions page" aria-label="SpatialHashMaxPerCell in context on the collisions page">→</a></h3>

`uint` · Constant, 32. Entries per bucket of the spatial hash self-collision files the points in. A point that finds its bucket full isn't filed, and its contacts go unseen for that step; <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#samplespatialhashoverflow">`SampleSpatialHashOverflow`</a> reports it. A crushed pile wants about 30: with 16, its contacts changed from step to step and it never came to rest.

## Methods

<h3 id="fabriceffect"><span class="method"><code>FabricEffect()</code></span> <a class="ctx" href="/docs/fabric-simulation/#fabriceffect-constructor" title="FabricEffect() in context on the quick start guide" aria-label="FabricEffect() in context on the quick start guide">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#fabriceffect">`FabricEffect(GraphicsDevice graphicsDevice, ContentManager contentManager, string effectPath = DefaultEffectPath)`</a> · Loads the solver through the content pipeline and takes a copy of it for this sheet, <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#shader">`Shader`</a>: one `ContentManager` hands every caller the same instance, and the buffers and uniforms belong to one sheet. Holds no sheet until <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>, which <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#rebuild">`Rebuild`</a> calls. The device needs `GraphicsProfile.HiDef`, the profile with a compute stage.

Throws `ArgumentNullException` for a `null` device or content manager, and `InvalidOperationException` when the effect has no `FabricTechnique` or lacks one of its eight passes, or when a shader header it can find disagrees with this assembly: `FabricShaderContractVersion` in <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-particle-fxh/">`FabricParticle.fxh`</a>, or `GroupSize` or `ContactCandidateCapacity` in `FabricSimulation.fxh`. It looks for the headers in `Content/Effects/Fabric/` beside the executable and in the folders above it; a deployment that kept only the compiled shader has nothing to compare, and passes.

| Parameter | Type | Description |
| --- | --- | --- |
| `graphicsDevice` | `GraphicsDevice` | The device the buffers are made on and the passes dispatched on. |
| `contentManager` | `ContentManager` | Loads the compiled solver. |
| `effectPath` | `string` | The solver's content path. Default: <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#defaulteffectpath">`DefaultEffectPath`</a>, the package's own. Name your own effect here when it wraps `FabricCompute.fx`, to add a wind function. |

<h3 id="apply"><span class="method"><code>Apply()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="Apply() in context on the sheet and step page" aria-label="Apply() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#apply">`Apply(FabricSettings settings)`</a> · Uploads every setting, cheap enough to call every frame: they take effect at the next step. The grid comes from <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>, never from the settings, and the spacing from the settings' <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#restlength">`RestLength`</a>. Makes the buffers self-collision, bending and pressure need, sized to the sheet, the first time they are switched on. A <a class="ref" href="/docs/fabric-simulation-glossary/sheet/fabric/">`Fabric`</a> calls it before every step, with the spacing it was built with: leave it to <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#update">`Update`</a> on a sheet a `Fabric` drives.

Everything is checked before anything is uploaded: throws `ArgumentNullException` for `null` settings, `ArgumentException` for a setting that isn't a finite number or a <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#solverfrequencyhz">`SolverFrequencyHz`</a> or `RestLength` that isn't positive, naming it, and `InvalidOperationException` for <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#useaerodynamicpressure">`UseAerodynamicPressure`</a> on a sheet over 4,096 points along its longer side.

| Parameter | Type | Description |
| --- | --- | --- |
| `settings` | <a class="ref" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/">`FabricSettings`</a> | The settings to upload. |

<h3 id="dispose"><span class="method"><code>Dispose()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-particle-methods" title="Dispose() in context on the sheet and step page" aria-label="Dispose() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#dispose">`Dispose()`</a> · Releases every buffer and this sheet's copy of the effect. The instance is unusable afterwards: its methods throw `ObjectDisposedException`, except `Dispose`, which does nothing the second time. Call it from `UnloadContent`.

<h3 id="readback"><span class="method"><code>ReadBack()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-particle-methods" title="ReadBack() in context on the sheet and step page" aria-label="ReadBack() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#readback">`ReadBack()`</a> · Returns <code><a href="/docs/fabric-simulation-glossary/solver/fabric-particle/">FabricParticle</a>[]</code>: a copy of every particle as of the latest step, in flat index order, see <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#particleindex">`ParticleIndex`</a>. It waits for the GPU to catch up, a full stall: use it for events and diagnostics, not every frame, and take one array for every check you run rather than one per question. An empty array before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

<h3 id="samplecoincidentcontacts"><span class="method"><code>SampleCoincidentContacts()</code></span> <a class="ctx" href="/docs/fabric-simulation-diagnostics/#fabriceffect-sampling-methods" title="SampleCoincidentContacts() in context on the diagnostics page" aria-label="SampleCoincidentContacts() in context on the diagnostics page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#samplecoincidentcontacts">`SampleCoincidentContacts()`</a> · Returns <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect-coincident-contacts/">`FabricEffect.CoincidentContacts`</a>: the contacts between points the solver found at the same spot with no history to tell them apart, since they began the step at one spot too, so it pushed them apart along an axis picked from their indices, a guess that can put two layers on each other's side. Only cloth crushed hard gets there. Always zero unless the solver was compiled with <a class="ref" href="/docs/fabric-simulation-glossary/hlsl/fabric-compute-fx/#fabric_count_coincident">`FABRIC_COUNT_COINCIDENT`</a> defined, since the count costs an atomic in the innermost contact loop. A GPU readback, so a stall: sample it a few times a second, not every frame. The counters behind every `Sample` method are fetched at most once per step, so sampling several of them together costs one stall. `default` before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

<h3 id="sampleheldfraction"><span class="method"><code>SampleHeldFraction()</code></span> <a class="ctx" href="/docs/fabric-simulation-diagnostics/#fabriceffect-sampling-methods" title="SampleHeldFraction() in context on the diagnostics page" aria-label="SampleHeldFraction() in context on the diagnostics page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#sampleheldfraction">`SampleHeldFraction()`</a> · Returns `float`: the share of the unpinned points held exactly still by <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#useresthold">`UseRestHold`</a>, over the steps since the last call. The stricter figure than <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#samplerestingfraction">`SampleRestingFraction`</a>: 1 for a pile at rest. Always 0 without the hold, 1 when every point is pinned, and 0 before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>. When the hold was off, or the pins changed, during the window, it starts a new window and returns the last figure meanwhile. A GPU readback, so a stall: sample it a few times a second, not every frame. The counters behind every `Sample` method are fetched at most once per step, so sampling several of them together costs one stall.

<h3 id="samplerestingfraction"><span class="method"><code>SampleRestingFraction()</code></span> <a class="ctx" href="/docs/fabric-simulation-diagnostics/#fabriceffect-sampling-methods" title="SampleRestingFraction() in context on the diagnostics page" aria-label="SampleRestingFraction() in context on the diagnostics page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#samplerestingfraction">`SampleRestingFraction()`</a> · Returns `float`: the share of the unpinned points inside the rest deadband, their carried motion discarded as noise, over the steps since the last call, so a settled sheet reads 1 however it is pinned. Not the same as still: the threads and contacts may go on moving a point inside it; <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#sampleheldfraction">`SampleHeldFraction`</a> is the figure for still. 1 when every point is pinned, and 0 before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>. When the deadband was off, or the pins changed, during the window, it starts a new window and returns the last figure meanwhile. A GPU readback, so a stall: sample it a few times a second, not every frame. The counters behind every `Sample` method are fetched at most once per step, so sampling several of them together costs one stall.

<h3 id="samplespatialhashoverflow"><span class="method"><code>SampleSpatialHashOverflow()</code></span> <a class="ctx" href="/docs/fabric-simulation-diagnostics/#fabriceffect-sampling-methods" title="SampleSpatialHashOverflow() in context on the diagnostics page" aria-label="SampleSpatialHashOverflow() in context on the diagnostics page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#samplespatialhashoverflow">`SampleSpatialHashOverflow()`</a> · Returns <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect-spatial-hash-overflow/">`FabricEffect.SpatialHashOverflow`</a>: what self-collision lost, the points the spatial hash couldn't file and the partners a full list left out, per step since the last call, and the deepest bucket and longest list wanted since the sheet was uploaded. A contact lost this way leaves no trace in the positions, so this is the one thing a check of your own on <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#readback">`ReadBack`</a>'s array can't work out: it tells cloth that passes through itself because a neighbor was never seen from cloth whose contacts were answered too weakly. After self-collision was off, it starts a new window and returns the last rates meanwhile. A GPU readback, so a stall: sample it a few times a second, not every frame. The counters behind every `Sample` method are fetched at most once per step, so sampling several of them together costs one stall. `default` before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

<h3 id="sampleworststepmotion"><span class="method"><code>SampleWorstStepMotion()</code></span> <a class="ctx" href="/docs/fabric-simulation-diagnostics/#fabriceffect-sampling-methods" title="SampleWorstStepMotion() in context on the diagnostics page" aria-label="SampleWorstStepMotion() in context on the diagnostics page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#sampleworststepmotion">`SampleWorstStepMotion()`</a> · Returns <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect-step-motion/">`FabricEffect.StepMotion`</a>: how close the sheet has come, since it was uploaded, to outrunning its own collision tests. Contacts are tested where the points end a step, not along the way, so a point that moves more than the cloth's thickness in one step can cross another layer with nothing able to see it. The thickness is a fraction of the spacing, so check at the resolution you ship; raising <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#solverfrequencyhz">`SolverFrequencyHz`</a> is the cheap fix. Measured only while <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#useselfcollision">`UseSelfCollision`</a> is on. A GPU readback, so a stall: sample it a few times a second, not every frame. The counters behind every `Sample` method are fetched at most once per step, so sampling several of them together costs one stall. `default` before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>.

<h3 id="setparticles"><span class="method"><code>SetParticles()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-particle-methods" title="SetParticles() in context on the sheet and step page" aria-label="SetParticles() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles(FabricParticle[] particles, int widthInParticles, int heightInParticles)`</a> · Makes the buffers for a sheet and uploads it, whole and untorn, restarting the clock, <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#time">`Time`</a> and <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#totalstepcount">`TotalStepCount`</a>, the diagnostics and the drawing lag. The next <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#update">`Update`</a> runs exactly one step, rather than catching up on the upload's stall. Call it again to resize: everything is checked and the new buffers made before the old ones are released, so a failure leaves the previous sheet running. Bind <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#particlebuffer">`ParticleBuffer`</a> again afterwards. <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#rebuild">`Rebuild`</a> calls it; a sheet given to a `Fabric`'s effect this way makes that `Fabric` throw until it is rebuilt.

The pins come from the records: a point with <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-particle/#ispinned">`IsPinned`</a> set is pinned where it is; any other with a positive <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-particle/#maxanchordistance">`MaxAnchorDistance`</a> hangs from the point <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-particle/#anchorindex">`AnchorIndex`</a> names, at most that far along the weave; and with none, no pin reaches it.

Throws `ArgumentNullException` for a `null` array; `ArgumentOutOfRangeException` for a width or height under 1; `ArgumentException` for an empty array, one whose length isn't width × height, more than <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#maxparticles">`MaxParticles`</a> particles, a position, previous position or rest angle that isn't finite, a NaN anchor distance, or an anchor outside the sheet; and `InvalidOperationException` when <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-particle/">`FabricParticle`</a> doesn't marshal to its <a class="ref" href="/docs/fabric-simulation-glossary/solver/fabric-particle/#sizeinbytes">`SizeInBytes`</a>.

| Parameter | Type | Description |
| --- | --- | --- |
| `particles` | <code><a href="/docs/fabric-simulation-glossary/solver/fabric-particle/">FabricParticle</a>[]</code> | The sheet, in flat index order: row by row, `row × widthInParticles + column`. |
| `widthInParticles` | `int` | Points across. Every neighbor is found from it, so a wrong one shears the rows apart. |
| `heightInParticles` | `int` | Points from the first row to the last. |

<h3 id="step"><span class="method"><code>Step()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="Step() in context on the sheet and step page" aria-label="Step() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#step">`Step()`</a> · Runs exactly one step: integrates the particles, applies the aerodynamic pressure when it is on, fills the spatial hash and gathers each point's partners when self-collision is on, then runs the constraint rounds, the folds solved before each round that solves them. One more <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#time">`Time`</a> and <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#totalstepcount">`TotalStepCount`</a>. Does nothing before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>; apply settings with <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#apply">`Apply`</a> first. Leaves <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#interpolationfraction">`InterpolationFraction`</a> where it was.

<h3 id="update"><span class="method"><code>Update()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-stepping-members" title="Update() in context on the sheet and step page" aria-label="Update() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#update">`Update(float elapsedSeconds)`</a> · Runs as many whole fixed steps as the time owed affords, up to <a class="ref prop" href="/docs/fabric-simulation-glossary/sheet/fabric-settings/#maxstepsperframe">`MaxStepsPerFrame`</a>, and drops any backlog beyond rather than spiral, setting <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#issaturated">`IsSaturated`</a>. Time left under a step waits for the next frame. Then moves <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#interpolationfraction">`InterpolationFraction`</a> on. Apply settings with <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#apply">`Apply`</a> first. Does nothing before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>, and the first call after it runs exactly one step, whatever the time.

| Parameter | Type | Description |
| --- | --- | --- |
| `elapsedSeconds` | `float` | The frame's time, in seconds. NaN and negative times count as none, and anything over 0.25 s as 0.25 s. |

<h3 id="updateparticles"><span class="method"><code>UpdateParticles()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-particle-methods" title="UpdateParticles() in context on the sheet and step page" aria-label="UpdateParticles() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#updateparticles">`UpdateParticles(FabricParticle[] particles)`</a> · Overwrites the particles of a sheet of the same size, without <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>' restarts: for live changes to positions, pins, anchors or rest angles on a sheet that keeps simulating, such as moving a pinned edge. The clock carries on. The pins come from the records, as for `SetParticles`. Take the array from a fresh <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#readback">`ReadBack`</a> every time: an older one rewinds the cloth. On a sheet a <a class="ref" href="/docs/fabric-simulation-glossary/sheet/fabric/">`Fabric`</a> drives, call <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#refreshanchors">`RefreshAnchors`</a> after changing which points are pinned. Does nothing before `SetParticles`.

Everything is checked before anything is uploaded: throws `ArgumentNullException` for a `null` array, and `ArgumentException` for one of another length, a position, previous position or rest angle that isn't finite, a NaN anchor distance, or an anchor outside the sheet.

| Parameter | Type | Description |
| --- | --- | --- |
| `particles` | <code><a href="/docs/fabric-simulation-glossary/solver/fabric-particle/">FabricParticle</a>[]</code> | Every particle, in flat index order, as many as <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#particlecount">`ParticleCount`</a>. |

<h3 id="updatetearstate"><span class="method"><code>UpdateTearState()</code></span> <a class="ctx" href="/docs/fabric-simulation-sheet/#fabriceffect-particle-methods" title="UpdateTearState() in context on the sheet and step page" aria-label="UpdateTearState() in context on the sheet and step page">→</a></h3>

<a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#updatetearstate">`UpdateTearState(uint[] tearState, bool anyTorn)`</a> · Uploads the damage: one word of <a class="ref" href="/docs/fabric-simulation-glossary/cuts/fabric-tear-flags/">`FabricTearFlags`</a> per point, with the dead-fold bits set as <a class="ref" href="/docs/fabric-simulation-glossary/sheet/fabric/">`Fabric`</a> sets them, which the solver expands into the mask its passes read. <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#cut">`Cut`</a>, <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#tear">`Tear`</a> and <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#cleartears">`ClearTears`</a> call it for you. An upload, so no stall. Does nothing before <a class="ref method" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#setparticles">`SetParticles`</a>. Throws `ArgumentNullException` for a `null` array, and `ArgumentException` for one whose length isn't <a class="ref prop" href="/docs/fabric-simulation-glossary/solver/fabric-effect/#particlecount">`ParticleCount`</a>.

| Parameter | Type | Description |
| --- | --- | --- |
| `tearState` | `uint[]` | The damage, one word per point, as <a class="ref method" href="/docs/fabric-simulation-glossary/sheet/fabric/#copytearstate">`CopyTearState`</a> returns it. |
| `anyTorn` | `bool` | Whether anything is torn: `false` lets the passes skip the mask altogether. |
